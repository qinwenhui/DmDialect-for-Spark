# DmDialect-for-Spark 项目设计说明文档

## 1. 项目概述

### 1.1. 项目背景与目标
**背景**：
Apache Spark 通过 JDBC 数据源访问关系型数据库时，由于不同数据库在 SQL 语法、数据类型、函数支持和连接行为上存在显著差异，需要通过 `JdbcDialect` 机制进行适配。达梦数据库（DM）作为国产数据库的重要代表，其 DM7 和 DM8 版本在特性上有所不同，且目前社区版 Spark 未提供官方的达梦方言支持。

**目标**：
本项目旨在开发一个**专业、可维护、可扩展**的 Spark JDBC 方言实现，代号为 `DmDialect-for-Spark`。
- **核心目标**：实现 Spark 4.1.1 与达梦数据库（DM7/DM8）的无缝、高效集成。
- **设计目标**：
  - **版本解耦**：通过模块化设计，同时支持 DM7 和 DM8，并预留对未来 DM 版本及多 Spark 版本的支持能力。
  - **开箱即用**：用户只需在 Spark 项目中引入本 JAR 包，即可自动生效，无需修改业务代码。
  - **生产级质量**：包含完善的类型映射、SQL 语法适配、错误处理和性能优化策略。

### 1.2. 项目定位
- **包名空间**：`cn.qinwh.spark.dm`
- **技术栈**：Scala 2.13.x（与 Spark 4.1.1 保持一致），Maven 构建。
- **交付物**：一个独立的 Maven 依赖（JAR 包），通过 `pom.xml` 引入即可使用。

## 2. 整体架构设计

### 2.1. 核心设计理念
采用**“抽象核心 + 版本特化 + 服务发现”**的设计模式。

1.  **抽象核心 (Core Abstraction)**：
    - 定义一个抽象的 `DmDialect` 基类，继承自 Spark 的 `JdbcDialect`。
    - 该基类封装所有达梦数据库通用的逻辑（如 URL 识别、基础类型映射、通用 SQL 规则）。
    - 它不依赖具体的 DM 版本，而是通过组合和委托，将版本相关的差异交给特化实现。

2.  **版本特化 (Version Specialization)**：
    - 针对 DM7 和 DM8 分别提供 `Dm7Dialect` 和 `Dm8Dialect` 实现类。
    - 这些特化类只负责处理该版本独有的特性，如 DM8 新增的 `JSON` 类型、`TIMESTAMP WITH TIME ZONE` 支持等。
    - 通过**版本检测器 (Version Detector)** 在运行时自动判断数据库版本，并动态选择最合适的方言实现。

3.  **服务发现 (Service Provider Interface, SPI)**：
    - 严格遵循 Java `ServiceLoader` 机制。
    - 在 JAR 包的 `META-INF/services` 目录下注册方言实现，使得 Spark 在启动时能自动发现并加载本方言。

4.  **配置驱动 (Configuration Driven)**：
    - 提供丰富的配置项，允许用户通过 Spark 的 JDBC Options 覆盖默认行为（如类型映射、性能参数），而无需重新编译代码。

### 2.2. 模块划分
项目采用清晰的包结构，确保高内聚、低耦合：

| 模块路径 | 职责描述 |
| :--- | :--- |
| `cn.qinwh.spark.dm.core` | **核心层**。包含 `DmDialect` 抽象基类、版本工厂、连接管理等核心逻辑。 |
| `cn.qinwh.spark.dm.version` | **版本管理层**。负责检测达梦数据库版本、定义版本特征矩阵，并管理 Spark 自身版本的兼容性。 |
| `cn.qinwh.spark.dm.types` | **类型映射层**。负责 Spark `DataType` 与达梦 JDBC 类型之间的双向转换，处理精度、标度等细节。 |
| `cn.qinwh.spark.dm.sql` | **SQL 构建层**。负责生成达梦兼容的 SQL 语句，包括 DDL (建表/删表)、DML (CRUD) 以及函数/表达式的翻译。 |
| `cn.qinwh.spark.dm.functions` | **函数映射层**。管理 Spark SQL 内置函数与达梦对应函数的映射关系，处理函数名差异和参数顺序。 |
| `cn.qinwh.spark.dm.config` | **配置管理层**。定义和管理所有可配置项，提供从 `JDBCOptions` 中解析配置的能力。 |
| `cn.qinwh.spark.dm.utils` | **工具层**。提供日志、常量、字符串处理、异常处理等通用工具类。 |

## 3. 关键机制设计

### 3.1. 方言自动发现与注册机制
**设计目标**：实现零侵入式集成。

**实现方案**：
1.  **SPI 注册**：
    - 在项目的 `src/main/resources/META-INF/services/org.apache.spark.sql.jdbc.JdbcDialect` 文件中，注册一个**代理类**或**工厂类**（例如 `cn.qinwh.spark.dm.core.DmDialectProvider`）。
    - 该文件内容示例：
      ```
      cn.qinwh.spark.dm.core.DmDialectProvider
      ```

2.  **运行时加载流程**：
    - Spark 启动时，通过 `ServiceLoader.load(JdbcDialect.class)` 扫描所有注册的方言。
    - 当执行 `spark.read.jdbc()` 或 `df.write.jdbc()` 时，Spark 会调用 `JdbcDialects.get(url)`。
    - 本项目的 `DmDialectProvider` 的 `canHandle(url)` 方法会匹配 `jdbc:dm://` 开头的 URL。
    - **关键点**：`DmDialectProvider` 本身不直接处理 SQL，而是作为一个**工厂**。它会在首次被调用时，通过 `DmVersionDetector` 探测数据库版本，然后返回一个具体的 `Dm7Dialect` 或 `Dm8Dialect` 实例。

### 3.2. 多版本达梦支持策略
**设计目标**：一套代码，兼容 DM7 和 DM8，并能优雅地应对未来版本。

**实现方案**：
1.  **版本检测 (Version Detection)**：
    - 在建立第一个 JDBC 连接后，执行 `SELECT * FROM V$VERSION` 或 `SELECT id_code FROM V$INSTANCE` 等达梦系统视图查询，解析出版本号（如 `7.6.0.197`、`8.1.2.192`）。

2.  **特征矩阵 (Feature Matrix)**：
    - 在 `DmVersion` 对象中定义各版本支持的特性。
    - 例如：
      - `JSON` 类型：仅 DM8 支持。
      - `LISTAGG` 函数：DM7 和 DM8 行为略有不同。
      - 分页语法：虽然都支持 `LIMIT/OFFSET`，但旧版本可能有性能差异。

3.  **条件化执行**：
    - 在 `Dm8Dialect` 中重写 `getCatalystType` 方法，专门处理 `JSON` 类型，将其映射为 Spark 的 `StringType`。
    - 在 `Dm7Dialect` 中则跳过该逻辑，走默认的 `StringType` 映射。

### 3.3. 类型映射系统设计
**设计目标**：保证数据精度和语义正确性，尤其是在时间和数值类型上。

**核心映射策略**：

| Spark 类型 | 达梦 DM8 类型 (推荐) | 达梦 DM7 类型 (推荐) | 备注 |
| :--- | :--- | :--- | :--- |
| `BooleanType` | `BIT` / `BOOLEAN` | `BIT` | |
| `ByteType` | `TINYINT` | `TINYINT` | |
| `ShortType` | `SMALLINT` | `SMALLINT` | |
| `IntegerType` | `INTEGER` / `INT` | `INTEGER` / `INT` | |
| `LongType` | `BIGINT` | `BIGINT` | |
| `FloatType` | `REAL` / `FLOAT` | `REAL` / `FLOAT` | |
| `DoubleType` | `DOUBLE PRECISION` | `DOUBLE PRECISION` | |
| `DecimalType(p,s)` | `DECIMAL(p,s)` / `NUMBER(p,s)` | `DECIMAL(p,s)` / `NUMBER(p,s)` | 严格控制精度和标度 |
| `StringType` | `VARCHAR2(n)` / `CLOB` | `VARCHAR2(n)` / `CLOB` | 超过 8188 字节时使用 `CLOB` |
| `BinaryType` | `BLOB` / `IMAGE` | `BLOB` / `IMAGE` | |
| `DateType` | `DATE` | `DATE` | |
| `TimestampType` | `TIMESTAMP` / `DATETIME` | `TIMESTAMP` / `DATETIME` | 默认映射为有本地时区的 `TimestampType` |
| `TimestampNTZType` | `TIMESTAMP` | `TIMESTAMP` | 通过配置 `preferTimestampNTZ=true` 启用，需注意 DM 本身无 NTZ 概念 |
| `YearMonthIntervalType` | `INTERVAL YEAR TO MONTH` | `INTERVAL YEAR TO MONTH` | DM8 原生支持 |
| `DayTimeIntervalType` | `INTERVAL DAY TO SECOND` | `INTERVAL DAY TO SECOND` | DM8 原生支持 |

**特殊处理**：
- **时间戳与时区**：Spark 3.x+ 引入了 `TimestampNTZType`。由于达梦数据库没有原生的 `TIMESTAMP WITHOUT TIME ZONE`，本项目将通过配置开关，允许用户选择是将 `TIMESTAMP` 映射为 Spark 的 `TimestampType` (LTZ) 还是 `TimestampNTZType`。在后一种模式下，读写时将跳过 Spark 的时区重基准（rebase）逻辑。
- **大对象 (LOB)**：`StringType` 在写入时，若长度不确定或超大，自动映射为 `CLOB`；`BinaryType` 映射为 `BLOB`。

### 3.4. SQL 语法适配设计
**设计目标**：生成高效、符合达梦语法的 SQL。

**关键适配点**：
1.  **标识符引用**：
    - 重写 `quoteIdentifier(colName: String)`，使用达梦的双引号 `"` 规则，并正确处理关键字转义和嵌套引号。

2.  **分页查询 (Pagination)**：
    - 达梦原生支持 `LIMIT n OFFSET m` 语法。
    - 因此，`supportsLimit` 和 `supportsOffset` 均返回 `true`。
    - `getLimitClause` 和 `getOffsetClause` 直接返回标准的 SQL 片段。

3.  **表采样 (Table Sampling)**：
    - 达梦支持 `TABLESAMPLE` 语法。
    - `supportsTableSample` 返回 `true`。
    - `getTableSample(sample)` 生成如 `TABLESAMPLE BERNOULLI (10)` 或 `TABLESAMPLE SYSTEM (10)` 的语句。

4.  **DDL 语句生成**：
    - **建表**：重写 `createTable` 方法，生成包含达梦特有存储选项的 `CREATE TABLE` 语句（如 `STORAGE(ON "MAIN", CLUSTERBTR)`）。
    - **修改表**：重写 `alterTable` 方法，适配达梦的 `ALTER TABLE ... MODIFY / ADD / DROP COLUMN` 语法。
    - **注释**：适配达梦的 `COMMENT ON TABLE ... IS ...` 和 `COMMENT ON COLUMN ... IS ...` 语法。

5.  **函数映射**：
    - 实现一个 `DmFunctionMapper`，维护 Spark SQL 函数到达梦函数的映射表。
    - **示例**：
      - Spark `datediff` -> 达梦 `DATEDIFF`
      - Spark `date_add` -> 达梦 `DATEADD`
      - Spark `if` -> 达梦 `DECODE` 或 `CASE WHEN`
      - Spark `concat_ws` -> 达梦 `CONCAT`（如果 DM 版本支持多参数 concat）

### 3.5. 连接管理与错误处理
**设计目标**：健壮、可控的连接行为和错误信息。

**连接工厂**：
- 重写 `createConnectionFactory`，允许注入达梦特有的连接属性（如 `characterEncoding=UTF-8`, `zeroDateTimeBehavior` 等）。
- 支持通过 JDBC URL 参数或 `dialect.conn.*` 前缀的配置项进行定制。

**异常分类**：
- 重写 `classifyException` 方法。
- 捕获达梦特定的 `SQLException`，根据其 `errorCode` 和 `SQLState`（`42xxx` 开头通常表示语法错误）进行分类。
- 将底层的数据库异常包装成 Spark 友好的 `AnalysisException` 或 `SparkRuntimeException`，提供更清晰的错误提示（例如：“达梦数据库不支持该数据类型”，“SQL 语法错误在第 X 行”）。

## 4. 配置系统设计

### 4.1. 配置层级
配置优先级从高到低：
1.  **DataFrame API 传入的 Options** (`spark.read.option(...)`)
2.  **Spark Conf** (`spark.conf.set("spark.dmdialect.xxx", "...")`)
3.  **默认值**

### 4.2. 核心配置项

| 配置项 Key | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `spark.dmdialect.preferTimestampNTZ` | Boolean | `false` | 是否优先将 TIMESTAMP 映射为 TimestampNTZType |
| `spark.dmdialect.legacyTimestampBehavior` | Boolean | `false` | 是否启用旧的 Timestamp 处理方式（兼容老版本） |
| `spark.dmdialect.performance.batchSize` | Int | `1000` | JDBC 批量写入的大小 |
| `spark.dmdialect.performance.fetchSize` | Int | `1000` | JDBC 读取时的 fetchSize |
| `spark.dmdialect.conn.useUnicode` | Boolean | `true` | 连接参数：是否使用 Unicode |
| `spark.dmdialect.conn.characterEncoding` | String | `UTF-8` | 连接参数：字符编码 |
| `spark.dmdialect.logging.enabled` | Boolean | `false` | 是否开启方言内部的 DEBUG 日志 |
| `spark.dmdialect.logging.logQueries` | Boolean | `false` | 是否在日志中打印生成的 SQL |

## 5. 开发与交付规划

### 5.1. Maven 项目配置要点
- **Scala 版本**：锁定为 `2.13.12`（与 Spark 4.1.1 兼容）。
- **Spark 依赖**：`spark-sql` 的 scope 设为 `provided`，因为最终运行环境由 Spark 集群提供。
- **达梦驱动依赖**：`DmJdbcDriver` 同样设为 `provided`，要求用户自行将达梦 JDBC 驱动放入 Spark 的 `jars/` 目录或通过 `--jars` 指定。
- **打包插件**：配置 `maven-source-plugin` 和 `maven-javadoc-plugin`，生成源码包和文档包，便于 IDE 阅读和调试。

### 5.2. 交付物清单
1.  **核心 JAR 包**：`dm-dialect-for-spark-1.0.0.jar`
2.  **源码包**：`dm-dialect-for-spark-1.0.0-sources.jar`
3.  **文档包**：`dm-dialect-for-spark-1.0.0-javadoc.jar`
4.  **API 文档**：Markdown 格式的在线文档或 ScalaDoc。
5.  **示例代码**：包含 Scala 和 Java 的读写示例项目。

## 7. 总结

本文档定义了 `DmDialect-for-Spark` 项目的宏观架构和设计原则。该项目不是一个简单的功能堆砌，而是一个**工程化、系统化**的解决方案。通过清晰的模块化、版本抽象和配置驱动设计，它将成为一个可靠、易用且可持续演进的 Spark-DM 连接器，能够显著降低用户在大数据分析场景下集成国产数据库的门槛。

开发团队应严格按照此文档定义的边界和接口进行编码，确保最终实现与设计意图一致。
